# Windows Server Infrastructure and Deployment Guide

## 1. Project Overview

This document provides an overview of the infrastructure used to host the RoomieReport frontend for the RateMyRoommates school competition project.

The purpose of this documentation is to explain the server environment, the technologies involved, the application deployment process, security considerations, and routine maintenance procedures.

For security purposes, this guide does not include machine-specific installation paths, private network information, authentication credentials, or sensitive configuration details.

## 2. Server Environment

The RoomieReport website is hosted on a Windows 11 computer configured to operate as a web server.

The hosting environment consists of the following technologies:

| Technology | Responsibility |
|---|---|
| Windows 11 | Host operating system |
| Apache HTTP Server 2.4 | Serves the frontend application |
| Cloudflare Tunnel | Provides secure connectivity between the host and Cloudflare |
| Cloudflare DNS | Associates the public domain with the website |
| Cloudflare SSL/TLS | Provides HTTPS access to website visitors |
| Node.js and npm | Builds the frontend application |
| React | Frontend user interface |
| Vite | Frontend development and build tool |
| TypeScript | Application programming language |
| GitHub | Source control and infrastructure documentation |

The server runs locally on a computer rather than on a third-party cloud virtual machine.

## 3. Infrastructure Architecture

The website uses the following request flow:

**Website Visitor → Cloudflare → Cloudflare Tunnel → Apache HTTP Server → React Frontend**

### Website Visitor

Visitors access the application through its public web domain using a modern web browser.

### Cloudflare

Cloudflare handles the public-facing connection, including DNS resolution and HTTPS.

### Cloudflare Tunnel

Cloudflare Tunnel establishes an outbound connection from the hosting computer to Cloudflare.

This allows the local web server to receive public website traffic without opening inbound ports on the network router.

### Apache HTTP Server

Apache receives requests forwarded by the tunnel and serves the compiled frontend application.

### React Frontend

The application is built using React, TypeScript, and Vite.

Apache serves the production files generated by the frontend build process.

**Note:** The current hosting environment serves the frontend prototype. Firebase backend integration is a separate development phase.

## 4. Apache Web Server Configuration

Apache HTTP Server 2.4 is installed and configured on Windows 11.

Its primary responsibilities include:

- Serving the compiled frontend website
- Responding to HTTP requests received through Cloudflare Tunnel
- Providing the application's main HTML entry point
- Serving JavaScript, CSS, images, and other static assets
- Supporting client-side routing for the React application

### Document Root

Apache uses a designated document root to store publicly served website files.

The document root contains the production application files, including the primary HTML file and associated assets.

The exact document root location is intentionally excluded from this public documentation.

### React Router Compatibility

Because the frontend uses client-side navigation, Apache must support requests for application routes that do not correspond to physical files.

A fallback directive is configured so that appropriate frontend routes can be handled by the React application.

The configuration uses Apache's `FallbackResource` capability to serve the main application entry point when necessary.

This prevents certain internal navigation paths from returning an Apache 404 error when refreshed.

### Configuration Validation

Whenever Apache configuration is modified:

1. Create a backup of the existing configuration.
2. Make the necessary change.
3. Validate the configuration syntax.
4. Resolve any reported errors before applying the change.
5. Restart or reload Apache when required.
6. Verify that the website remains accessible.
7. Confirm that client-side navigation continues to function correctly.

The specific server configuration files and local installation details are maintained privately.

## 5. Cloudflare Infrastructure

Cloudflare provides the public-facing networking components for the website.

### DNS Configuration

The project's public domain is configured through Cloudflare DNS.

DNS records associate the website's supported hostnames with the existing Cloudflare Tunnel.

### Cloudflare Tunnel

A named Cloudflare Tunnel is configured to connect the hosting computer to Cloudflare's network.

The tunnel client runs as a background service on Windows.

The tunnel forwards website requests to Apache using a locally configured HTTP service.

The local destination, tunnel credentials, and machine-specific configuration are not included in this repository.

### HTTPS

Cloudflare provides HTTPS access for visitors.

The connection between the visitor and Cloudflare is encrypted using TLS.

The tunnel uses its own secure connection to Cloudflare, allowing the local Apache service to remain inaccessible directly from the public internet through this configuration.

### Advantages of This Architecture

- Public HTTPS access
- No router port forwarding required
- Centralized DNS management
- Separation between public traffic and the local hosting environment
- Ability to update the frontend without recreating the tunnel

## 6. Frontend Deployment Process

The RoomieReport frontend is maintained separately in the team's shared GitHub repository.

The infrastructure maintainer is responsible for publishing approved frontend builds to the web server.

### Step 1: Obtain Approved Frontend Changes

Retrieve the latest approved application version from the team's repository.

Verify that the source is from the intended project and branch.

### Step 2: Prepare the Build Environment

Confirm that Node.js and npm are installed and compatible with the frontend project.

Ensure the required dependencies are installed.

### Step 3: Generate the Production Build

Use the project's configured production build command.

For the current Vite-based frontend, the standard command is:

`npm run build`

The build process generates static application files in an output directory.

### Step 4: Verify the Build

Before deployment:

- Confirm the build completed successfully.
- Verify that the output contains the application's main HTML file.
- Check that required JavaScript and CSS assets were generated.
- Review any build warnings or errors.

### Step 5: Back Up the Existing Deployment

Create a backup of the currently deployed website files before replacing them.

This provides a recovery option if the new version does not function as expected.

### Step 6: Deploy Production Files

Copy the contents of the generated production build directory into Apache's configured document root.

Only files required to serve the website should be published.

Development dependencies, source-control metadata, private configuration, and secrets must not be placed in the publicly served directory.

### Step 7: Verify the Deployment

Test the application locally and through its public domain.

Confirm that:

- The homepage loads.
- Application assets load correctly.
- Navigation between pages works.
- Internal pages can be refreshed.
- The website displays on desktop and mobile devices.
- HTTPS remains available.

### Step 8: Document the Deployment

Record the deployment date, application version or commit reference, verification results, and any notable issues in the infrastructure change log.

## 7. Windows Service Management

The hosting computer runs Apache and the Cloudflare Tunnel client as Windows services.

The services are intended to operate automatically without requiring the application to be launched manually after every system startup.

### Routine Service Checks

The infrastructure maintainer should verify that:

1. Apache is running.
2. The Cloudflare Tunnel client is running.
3. Automatic startup is configured where appropriate.
4. The hosting computer has an active network connection.
5. The Cloudflare dashboard reports a healthy tunnel connection.

Administrative service changes should be performed only by authorized users.

## 8. Server Availability

The current infrastructure uses a locally hosted Windows computer.

Website availability therefore depends on the computer remaining powered on, awake, and connected to the internet.

Potential causes of interruption include:

- Computer sleep or hibernation
- Network disconnection
- Apache service interruption
- Cloudflare Tunnel disconnection
- System restart or power failure

### Availability Practices

For important demonstrations:

- Keep the host powered on.
- Prevent unintended sleep.
- Verify service availability.
- Confirm internet connectivity.
- Test the website from an external device.
- Prepare backup screenshots or a recorded demonstration.

## 9. Troubleshooting Approach

When the website becomes unavailable, use a structured troubleshooting process.

### Stage 1: Check the Hosting Computer

Confirm that the operating system is running and connected to the internet.

### Stage 2: Check Apache

Verify that the local web server is active and that the frontend loads locally.

### Stage 3: Check Cloudflare Tunnel

Check the tunnel's reported connection status.

If the tunnel is disconnected, investigate the tunnel service and network connectivity.

### Stage 4: Check DNS and Public Access

Verify that the website hostnames resolve and point to the intended Cloudflare configuration.

### Stage 5: Verify the Application

After restoring connectivity, test navigation and frontend functionality.

A previous Cloudflare Error 1033 incident was resolved after tunnel connectivity returned. Laptop sleep was considered a possible cause, but it was not definitively confirmed.

## 10. Security Practices

The infrastructure is documented using security-conscious practices.

### Sensitive Information

The following information is intentionally excluded from this repository:

- Authentication credentials
- Cloudflare Tunnel tokens
- API keys
- Private cryptographic keys
- Exact machine-specific installation paths
- Personal usernames and device identifiers
- Private network configuration
- Sensitive logs
- Student personal information

### Public File Management

Only intended website assets should be served by Apache.

Private configuration, credentials, development files, and unnecessary server administration interfaces must not be exposed through the public website.

### Software Maintenance

The operating system, Apache, Cloudflare Tunnel client, and supporting tools should be maintained and updated through a controlled process.

Updates should be tested to avoid introducing unexpected downtime during demonstrations.
